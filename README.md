# dsh-plugin-shop-dashboard

店铺数据看板 —— 把「店铺账号管理」（[dsh-plugin-shop-accounts](https://github.com/monagisa/dsh-plugin-shop-accounts)）已经采集到的报表工作簿，聚合成一张经营看板。

不重新采集、不登录、不写数据：只读本地采集产物；缺数据的地方给占位说明，而不是假装 0。

## 功能

- **主页面左上角**有一枚「经营看板」胶囊：直接显示近 7 天成交金额 / 访客数 / 成交转化率，点开就是完整看板。
- 设置里多一项「数据看板」（与「账号管理」并列）。
- 四组指标页签：**经营总览**（9 张）、**流量转化**（9 张）、**商品供给**（10 张）、**运营推广**（8 张）。
- 店铺下拉：全部店铺合并，或只看一家店。
- 时间范围：近 7 / 14 / 30 / 90 天、本月、上月、**自定义起止日期**，默认统计到昨天（当天报表通常还没归档）。
- 走势粒度：日 / 周 / 月；显示口径：合并 / 按平台分开。
- 卡片：按指标色调着色，带当期值、与上期比较、走势缩略线；当期数据不足一半时挂「部分覆盖」徽标。
- 比较文案按口径给结果：`首期缺失`、`上期为零，无法计算变化率`、`上期为负数，无法比较`、`数据不完整，无法比较`、`与上期持平`；「越高越差」的指标（退款、花费、跳失率、CPC、CPL）涨了按坏方向标红。

## 口径

| 指标 | 口径 |
| --- | --- |
| 成交金额 / 退款金额 / 推广花费 / 访客数 / 支付买家数 / 支付件数 | 直接相加 |
| 客单价 | 成交金额 ÷ 支付买家数 |
| 成交转化率 | 支付买家数 ÷ 访客数 |
| 销售收入 | 成交金额 − 退款金额 − 推广花费 |
| ROI | 推广成交额 ÷ 推广花费 |
| CPC | 推广花费 ÷ 点击量 |
| CPL | 推广花费 ÷ 线索量 |
| 跳失率 / 平均停留时长 | 按访客数加权平均 |
| 商品数 / 动销商品数 / 动销率 / 有访问商品数 / 零成交商品 / 高流量低转化商品 | 取区间末值（存量类，不画走势）；当天没有商品明细表时留空 |

- 平台列名差异按别名识别：成交金额 / 支付金额 / 用户支付金额、推广花费 / 全站推广花费 / 投放消耗、成功退款金额 / 退款金额、支付子订单数 / 成交订单数、被访问商品数 / 有访问商品数等。
- 日期列兼容「日期」「统计日期」以及 `20261124` 这类紧凑格式。
- 百分比列按列判定小数还是百分数（整列不超过 1.5 视为小数，整列 ×100），避免 72.5% 显示成 7250%。
- 商品明细表按「日期 + 商品ID」累积后派生存量类指标（该商品当天有成交才算动销，有访客但没成交算零成交）。
- 只算店铺级：带商品 / 场景 / 人群 / 来源维度的表按明细烦过——载体类型、投放时段这类维度只取「全部 / 不限 / 整体」的汇总行；商品明细表按「日期 + 商品ID」去重后并入。
- 比率一律按分子 / 分母重算，不把各店比率再平均。

## 安装

需要先装并跑过 `dsh-plugin-shop-accounts`（数据来源）。然后：

1. 设置 → 插件 → 从本地安装 → 选本目录（或打好包的 `.tgz`）；
2. 完全退出 DSH 再打开；
3. 设置 → 数据看板。

源码开发：把本目录放到（或链到）profile 的 `node_modules` 下，重启 DSH。

## 数据来自哪里

默认读 `~/.dsh/shop-accounts`：

- `accounts.json`：店铺列表；
- `collection/<店名_平台_尾号>/jobs/*/artifacts/采集数据_*.xlsx`：成品工作簿（每店每天一份，五域分表）。

数据目录被 `DSH_SHOP_ACCOUNTS_DIR` 或指针文件 `~/.dsh/shop-accounts.dir` 改过时，本插件跟着同一个目录走。

## 接口

`GET /shop-dashboard/dashboard`

| 参数 | 说明 |
| --- | --- |
| `store` | `all` 或账号 id |
| `days` | `7` / `14` / `30` / `90` |
| `range` | `month`（本月）或 `lastmonth`（上月） |
| `from`、`to` | 自定义区间 `YYYY-MM-DD`，优先于 `days` / `range` |
| `group` | `overview` / `traffic` / `product` / `promotion` / `all` |
| `grain` | `day` / `week` / `month` |
| `mode` | `combined`（合并）或 `by-platform`（按平台分开） |

只接受本插件界面发来的请求（带 `X-DSH-Shop-Dashboard: 1` 头）。

## 自检

```bash
node tools/check-syntax.mjs   # 语法检查（含客户端 bundle 的编译检查）
node test/features.mjs        # 骨架 + 看板口径 + 真实数据（有就验）
```

## 已知限制

- 只读，且只算「已经采到」的数据；没采过的店或太旧的数据会显示占位。
- 「多平台推广看板」「单店数据看板」「经营周报」「流量转化诊断」还没做。
- 商品供给的存量类指标（商品数 / 动销商品数 / 零成交商品）依赖采集侧提供对应列；没有就给空。
- 自定义时间的起止日期输入框还没做（接口已支持 `from` / `to`）。
