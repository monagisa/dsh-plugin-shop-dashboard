# dsh-plugin-shop-dashboard

店铺数据看板 —— 把「店铺账号管理」（[dsh-plugin-shop-accounts](https://github.com/monagisa/dsh-plugin-shop-accounts)）已经采集到的报表工作簿，聚合成一张经营看板。

不重新采集、不登录、不写数据：只读本地采集产物，缺数据的地方给占位说明，而不是假装 0。

## 功能

- 设置里多一页「数据看板」（与「账号管理」并列）。
- 页签：多平台经营看板（可用）、多平台推广看板 / 单店数据看板（占位）。
- 店铺下拉：全部店铺合并，或只看一家店。
- 时间范围：近 7 天 / 近 30 天，默认统计到昨天（当天报表通常还没归档）。
- 8 张核心指标卡：成交金额、退款金额、推广花费、销售收入、客单价、访客数、支付买家数、成交转化率。
- 每张卡：当期值、较上期变化、每天走势；数据不全时显示「数据不完整」「无法比较 上期 —」。

## 口径

| 指标 | 口径 |
| --- | --- |
| 成交金额 / 退款金额 / 推广花费 / 访客数 / 支付买家数 | 直接相加 |
| 客单价 | 成交金额 ÷ 支付买家数 |
| 成交转化率 | 支付买家数 ÷ 访客数 |
| 销售收入 | 成交金额 − 退款金额（平台报表没有统一列） |

- 平台列名差异按别名识别：成交金额 / 支付金额、推广花费 / 全站推广花费、成功退款金额 / 退款金额…
- 日期列兼容「日期」「统计日期」以及 `20261124` 这类紧凑格式。
- 只算店铺级：带商品 / 场景 / 人群 / 来源维度的表按明细跳过；载体类型、投放时段这类维度只取「全部 / 不限」的汇总行。

## 安装

需要先装并跑过 `dsh-plugin-shop-accounts`（数据来源）。然后：

1. 设置 → 插件 → 从本地安装 → 选本目录（或打好包的 `.tgz`）；
2. 完全退出 DSH 再打开；
3. 设置 → 数据看板。

源码开发：把本目录放到（或链到）profile 的 `node_modules` 下，重启 DSH。

## 数据来自哪里

默认读 `~/.dsh/shop-accounts`：

- `accounts.json`：店铺列表；
- `collection/<店名_平台_尾号>/jobs/*/artifacts/采集数据_*.xlsx`：成品工作簿。

数据目录被 `DSH_SHOP_ACCOUNTS_DIR` 或指针文件 `~/.dsh/shop-accounts.dir` 改过时，本插件跟着同一个目录走。

## 接口

`GET /shop-dashboard/dashboard?days=7|30&store=all|<账号 id>`

只接受本插件界面发来的请求（带 `X-DSH-Shop-Dashboard: 1` 头）。

## 自检

```bash
node tools/check-syntax.mjs   # 语法检查（含客户端 bundle 的编译检查）
node test/features.mjs        # 骨架 + 看板口径 + 真实数据（有就验）
```

## 已知限制

- 只读，且只算「已经采到」的数据；没采过的店或太旧的数据会显示占位。
- 「多平台推广看板」「单店数据看板」「经营周报」「流量转化诊断」还没做。
- 自定义时间范围还没做（目前只有近 7 / 30 天）。
